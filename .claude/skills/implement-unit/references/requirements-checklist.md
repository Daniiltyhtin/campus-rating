# Цепочка «требование → критерий → проверка»

Используй существующие ID плана (R, AE, KTD); параллельную нумерацию не заводи.

| Требование (R/KTD) | Пример или граница (AE / сценарий) | Критерий готовности | Проверка (тест или команда) |
|---|---|---|---|
| R11 — штраф по слотам | AE1: 3 слота по −20, четвёртого нет | После 12:03:01 АР = 940 | `PenaltyJobIT#basicPenalty` |

Правила:
- Каждое правило и каждый граничный случай покрыты хотя бы одним критерием.
- Каждый критерий — хотя бы одной проверкой.
- Негативные ветки (отказ, повтор, гонка, нет прав) — отдельные строки.
- Если у юнита есть побочные эффекты (письма, проводки, события) — отдельная строка на повторное выполнение.
- Строка без проверки — пометь «не проверено» и объясни в отчёте.
