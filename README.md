# Campus Rating

MVP университетской социальной сети: академический рейтинг (АР), баллы учебной (БУА) и общественной (БОА) активности, контрольные точки, мероприятия, лента наград и рейтинги групп. Проект хакатона 2026, разрабатывается командой вместе с ИИ-агентами.

## Запуск

Из корня клона, с установленным Docker и Compose v2:

```bash
docker compose up
```

Образы собираются автоматически; `.env` не нужен. После готовности сервисов откройте [http://localhost:8080](http://localhost:8080) и войдите одним из демо-аккаунтов.

Стенд работает в режиме `demo`: при каждом старте backend схема БД и загруженные файлы пересоздаются, изменения теряются. Дедлайны и время мероприятий отсчитываются от запуска. Подтверждение email явно выключено (`EMAIL_VERIFICATION=off`); SMTP и Mailpit для запуска не нужны.

Все опубликованные порты доступны только на `127.0.0.1`:

| Сервис | Адрес | Назначение |
|---|---|---|
| web | `http://localhost:8080` | SPA и прокси `/api/` на backend |
| backend | `http://localhost:8081` | API для разработки; Vite проксирует сюда `/api` |
| PostgreSQL | `127.0.0.1:5433` | Подключение локальных инструментов к БД |

Для разработки frontend: `npm --prefix frontend ci`, затем `npm --prefix frontend run dev`. Локальный Vite использует backend запущенного стека. Необязательные параметры БД описаны в `.env.example`.

Запуск с ожиданием готовности и остановка:

```bash
docker compose up -d --build --wait
docker compose down
```

`docker compose down` сохраняет тома; `docker compose down -v` удаляет БД и загруженные файлы. Перезапуск backend в режиме `demo` пересоздаёт схему и при сохранённом томе.

## Демо-история

Каждый студент начинает с 1000 АР; штрафы уменьшают рейтинг, награды начисляются в БУА или БОА. Балансы подтверждены журналом проводок.

| Объект | Что можно показать |
|---|---|
| «Лабораторная работа: анализ данных», точка `21001` | Дедлайн 20 минут назад, стоимость 60 АР, штраф 4 АР раз в 60 секунд; просроченные, сданные, принятая и возвращённая работы со ссылками |
| «Проект: модель университетского сервиса», точка `21002` | Дедлайн через два дня; сдача и отзыв до дедлайна |
| «Волонтёрский день кампуса» | Прошедшая общественная активность с записями и наградами на уровнях 25, 50, 75 и 100 % |
| «Учебная конференция» | Прошедшая учебная активность с подтверждениями; общий месячный бюджет Петрова для ИВТ-21 потрачен на 950 из 1000, для ИВТ-22 — на 500 из 1000 |
| «Клуб настольных игр» | Будущая общественная активность с открытой записью |
| Лента наград и рейтинг ИВТ-21 | Награды с автором и источником, студенты с разным АР |

Штрафы у открытых просроченных задач продолжают начисляться после запуска до стоимости точки. Бюджет относится к текущему календарному месяцу по Москве и общий для БУА и БОА.

## Сценарий показа

1. **Студент.** Войдите Смирновой, откройте задачи: у лабораторной просрочка и списано 60 АР. В будущей задаче сдайте ссылку, например `https://example.org/report`, затем отзовите сдачу до дедлайна. Откройте ленту наград и запись на клуб настольных игр. Под Лебедевой покажите комментарий возврата «Добавьте выводы». Смирнова — староста: на «Главной» карточка «Заявки в группу ИВТ-21», кнопкой «Проверить заявки» подтвердите заявку Орлова; войдите Орловым — у него появились назначения по открытым точкам.
2. **Преподаватель.** Войдите Петровым, откройте лабораторную и таблицу статусов. Примите работу Кузнецова, верните работу Ивановой с комментарием. Покажите рейтинг ИВТ-21 по АР. Откройте активности, подтверждённых участников и бюджет: у ИВТ-21 осталось 50 баллов в месяце запуска стенда (по Москве); если с запуска сменился месяц, выберите предыдущий месяц или перезапустите backend. Создайте будущую точку для доступной группы.
3. **Администратор.** Войдите администратором и покажите справочники. Экраны допуска преподавателей пока отсутствуют: получите список через `GET /api/v1/admin/teachers`, затем допустите Волкова запросом `POST /api/v1/admin/teachers/2002/approval` с JSON `{"departmentId":101}`. Войдите Волковым до и после допуска, чтобы показать появившийся доступ к группам и созданию точки.

Для изменяющих запросов API сначала получите cookie через `GET /api/v1/auth/csrf` и передайте её значение в `X-XSRF-TOKEN`, сохраняя cookie сессии. После входа, выхода и смены пароля получите свежий токен. Для допуска используйте сессию администратора; форматы запросов описаны в [API-контракте](docs/spec/api/).

## Переменные prod

Первый запуск профиля `prod` требует явных переменных процесса `CAMPUS_BOOTSTRAP_ADMIN_EMAIL`, `CAMPUS_BOOTSTRAP_ADMIN_PASSWORD` и `EMAIL_VERIFICATION=off`. Первому администратору обязательна смена пароля; при существующем ADMIN новые bootstrap-значения игнорируются. Режим `required` требует настроенного SMTP — без него backend не стартует.
