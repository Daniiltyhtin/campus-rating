# U13 — независимые HTTP acceptance tests

Источники ожиданий: R/AE планов 2026-11-12-004/005/006/007; план исполнения 008.
Тесты вызывают приложение через RestTestClient, используют PostgreSQL Testcontainers.
Production и спецификация tester не менялись. Коммитов нет.

## Зафиксированные прогоны

1. `backend/mvnw.cmd -f backend/pom.xml -Dtest=U13AdminSemestersIT test`:
   15 tests, 14 failures, 0 errors. HTTP 404 на отсутствующих admin/settings и
   admin/semesters. Лог u13-first-red.log. Первый технический сбой BOM исправлен
   до этого HTTP red.
2. `backend/mvnw.cmd -f backend/pom.xml -Dtest=U13AdminUsersIT,U13AdminImportIT,U13AdminSubmissionIT test`:
   23 tests, 18 failures, 0 errors. HTTP 404 на отсутствующих users/import/audit;
   все 4 теста submission прошли. Лог u13-rest-red.log.
3. `backend/mvnw.cmd -f backend/pom.xml -Dtest=U13RequiredMailConfigTest,U13AdminMailIT,U13RequiredMailIT test`:
   старый guard подтверждён failure requiredWithSmtpIsAvailableForU13 с текстом
   `required is unavailable until master-U15`, required без SMTP прошёл.
   HTTP mail тогда не проверен: контекст сломан отсутствующим StudentMember.class
   во время пересборки общего target. Лог u13-mail-red.log.
4. Исполнитель повторил первые 22 теста: семестры 15/15, пользователи 5/7.
   Два дефекта подготовки исправлены tester: PENDING задаётся явно; поисковая
   строка не кодируется перед RestTestClient повторно. Ожидания не ослаблены.
5. Финальный повтор u13-final-red.log остановлен по согласованию общего target.
   Последние добавленные scheduler/quota/rollback и переработанные mock-mail tests
   пока не прогонялись. Последний исходник целиком не объявляется зелёным.

Повтор всего набора одним процессом:
`backend/mvnw.cmd -f backend/pom.xml "-Dtest=U13*,MailModeConfigTest" test`
Либо IT через Failsafe и конфигурационные Test отдельно. Scheduler-проверки включают
настоящий минутный job, ожидают до 90 с первый результат и 65 с отсутствие повтора.
JUnit parallel не включать.

## Ограничения и несоответствия

- 004/AE5 требует исходные АР 1200, но текущий CHECK ledger_balance запрещает >1000.
  Невозможно подготовить такой вход через действующий LedgerApi; тест для 1200
  не придуман, ограничение сообщено исполнителю. Предел для исходных 900 проверяется.
- UI (меню, диалоги, отмена, скрытие кнопок/аудита, ширины 360/1280) не входит в эти
  HTTP tests; требуются проверки исполнителя/UI tester.
- Дополнительные stress-сценарии плана 008 (гонки reset/import/consume, zip-bomb,
  смена N между пачками >500 студентов), точное округление минимума при дробном poll
  отдельным контекстом и проверка логов на отсутствие секретов здесь не покрыты.
- Полный журнал/история аудита не выводится HTTP-контрактом: проверяется последнее
  действие, а не внутренний формат хранения всей истории.
