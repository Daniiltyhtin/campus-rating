# ADR006. Liquibase и formatted SQL

- **Статус:** `accepted`.
- **Связанные KTD:** KTD13.
- **Связанные требования и примеры:** R4, R39; отдельного AE для миграций в мастер-плане нет.
- **Источник решения:** [мастер-план](../plans/2026-10-31-001-feat-campus-rating-mvp-plan.md#key-technical-decisions).

## Контекст

Параллельные ветки добавляют схему разных модулей. Порядок слияния не должен мешать применению ещё не применённых изменений. Чистый запуск compose должен автоматически загружать справочники и демо-данные; тесты должны обходиться без демо-данных.

## Решение

Схема управляется Liquibase в формате formatted SQL. Changeset'ы находятся в `db/changelog/<module>/<yyyyMMddHHmm>-<desc>.sql`, id — `<автор>:<метка>`.

Master-changelog подключает папки через `includeAll` в порядке зависимостей: `settings`, `directory`, `identity`, `ledger`, `checkpoint`, `activity`, `feed`, `poll`, `admin`, `notification`, затем `demo`. Добавление файла в папку не требует правки master-changelog. Liquibase применяет любой ещё не применённый changeset независимо от порядка слияния веток.

Демо-данные помечены `context: demo`: compose включает контекст, тесты запускаются без него. Справочные данные используют `runOnChange`. Демо-пароли видны только в README.

Применённый changeset не редактируется: контрольная сумма защищает историю, исправление оформляется новым changeset'ом. Тесты на Testcontainers и CI накатывают changelog на пустую базу.

## Последствия

### Положительные

- Новые файлы модулей не создают конфликт правок master-changelog между параллельными ветками; ещё не применённые изменения не зависят от порядка слияния.
- Контекст отделяет демо-данные compose от тестов, а `runOnChange` предусмотрен для справочных данных.
- Накат на пустую базу в тестах и CI обнаруживает сломанную историю до запуска на другой машине.

### Отрицательные

- Исправление уже применённого изменения требует нового changeset'а; переписать историю нельзя.
- Нужно соблюдать порядок зависимостей модулей в master-changelog и разделение контекстов compose и тестов.
- Проверка истории требует наката changelog на пустую PostgreSQL в Testcontainers и CI.

## Рассмотренные альтернативы

KTD13 фиксирует выбор Liquibase вместо Flyway: применение не зависит от порядка слияния веток, есть контексты для сида и откат при необходимости. Это не утверждает наличия готового отката для каждого будущего changeset'а.

## Проверка

KTD13 требует наката changelog на пустую базу в Testcontainers и CI. R4 и R39 требуют автоматической загрузки справочников и демо-пользователей при чистом запуске compose. Отдельного AE нет; фактическая проверка схемы и сида относится к реализации приложения.
