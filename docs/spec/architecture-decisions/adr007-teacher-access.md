# ADR007. Доступ преподавателя: список почт и доступные группы

- **Статус:** `accepted`.
- **Связанные KTD:** KTD23.
- **Связанные требования и примеры:** R2, R3, R49, R7, R17, R21, R22, R24, R25, R33; отдельного AE в мастер-плане нет.
- **Источник решения:** [мастер-план](../plans/2026-10-31-001-feat-campus-rating-mvp-plan.md#key-technical-decisions).

## Контекст

ТЗ разрешает преподавателю регистрироваться самому. Без ограничений любой посетитель выбирает роль «Преподаватель», создаёт точку для любой группы и запускает штрафы или начисляет баллы своими активностями. Проверка владельца ресурса (R3) этого не останавливает: ресурс он создал сам. Риск найден ревью безопасности UX-карты (U21a) и закрыт решением команды.

## Решение

- Регистрация с ролью `TEACHER` проходит только для email из списка преподавателей (`TeacherAllowlist`), который ведёт администратор: импорт списка и ручное редактирование. Email из списка не регистрируется студентом. Демо-преподаватели попадают в список из сида.
- Доступные группы преподавателя (`TeacherScope`) — группы факультета его кафедры плюс выдачи администратора (`TeacherGrant`): отдельная группа, весь факультет, курс факультета или курс на всех факультетах. Курс вычисляется из года набора группы на текущую дату. Точки, активности и опросы создаются только для доступных групп; рейтинги, бюджеты и аналитика читаются только по ним.
- Правило считает одна функция модуля `identity`; `checkpoint`, `activity`, `poll`, `feed` и `analytics` вызывают её. Проверка владельца ресурса остаётся отдельной.

## Последствия

### Положительные

- Посторонний не получает полномочий преподавателя; регистрация по ТЗ сохраняется.
- У администратора нет очереди ручных подтверждений: список загружается одним файлом.
- Межфакультетские кафедры работают через выдачи: общий предмет вроде математики — выдачей факультета, курса факультета или курса на всех факультетах, а не десятком отдельных групп.
- Выдача курса не устаревает: со сменой учебного года она переходит на новый набор.

### Отрицательные

- Новый преподаватель не зарегистрируется, пока администратор не добавит его email.
- Смена кафедры, снятие выдачи или смена учебного года меняет доступ сразу; преподаватель с выдачей курса теряет прошлогодние группы 1 сентября; уже созданные точки и активности остаются у автора.
- Ещё два справочника и экраны админки (U13).

## Рассмотренные альтернативы

- Закрытый стенд с открытой саморегистрацией и принятым риском — отклонено: стенд будет на сервере (U22).
- Ручное подтверждение каждого преподавателя администратором — отклонено: очередь заявок и лишнее состояние «ждёт допуска».
- Жёсткое ограничение факультетом кафедры — отклонено: кафедры ведут занятия на других факультетах.

## Проверка

Тесты U5 (регистрация по списку, `TeacherScope`), U7, U9, U11, U16, U17 (403 вне доступных групп), U13 (импорт списка, выдача и снятие группы, факультета, курса факультета и курса на всех факультетах). Это запланированные проверки, а не выполненные.
