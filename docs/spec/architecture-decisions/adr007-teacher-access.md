# ADR007. Доступ преподавателя: список почт и доступные группы

- **Статус:** `accepted`.
- **Связанные KTD:** KTD23.
- **Связанные требования и примеры:** R2, R3, R31, R32, R36, R49, R7, R17, R21, R22, R24, R25, R33; отдельного AE в мастер-плане нет.
- **Источник решения:** [мастер-план](../plans/2026-10-31-001-feat-campus-rating-mvp-plan.md#key-technical-decisions).

## Контекст

ТЗ разрешает преподавателю регистрироваться самому. Без ограничений любой посетитель выбирает роль «Преподаватель», создаёт точку для любой группы и запускает штрафы или начисляет баллы своими активностями. Проверка владельца ресурса (R3) этого не останавливает: ресурс он создал сам. Риск найден ревью безопасности UX-карты (U21a) и закрыт решением команды.

## Решение

- Регистрация с ролью `TEACHER` открыта, как в ТЗ: email, пароль, ФИО и кафедра из справочника. Полномочия даёт допуск (`TeacherApproval`). Его ставит подтверждение email из списка преподавателей (`TeacherAllowlist`, ведёт администратор импортом и вручную) — тогда кафедра берётся из записи списка, — или администратор по заявке: при `off`, когда почта не проверяется, и для email вне списка. Отклонённая заявка удаляет аккаунт. Email из списка не регистрируется студентом. Демо-преподаватели допущены сидом.
- Без допуска вход работает, но доступных групп нет; модули не проверяют допуск отдельно, это делает пустой `TeacherScope`.
- Доступные группы преподавателя (`TeacherScope`) — группы факультета его кафедры плюс выдачи администратора (`TeacherGrant`): отдельная группа, весь факультет, курс факультета или курс на всех факультетах. Курс вычисляется из года набора группы на текущую дату. Точки, активности и опросы создаются только для доступных групп; рейтинги, бюджеты и аналитика читаются только по ним.
- Правило считает одна функция модуля `identity`; `checkpoint`, `activity`, `poll`, `feed` и `analytics` вызывают её. Проверка владельца ресурса остаётся отдельной.

## Последствия

### Положительные

- Посторонний не получает полномочий преподавателя; регистрация по ТЗ работает в любом режиме подтверждения email, в том числе на локальном стенде жюри.
- При `required` у администратора нет очереди для преподавателей из списка: список загружается одним файлом.
- Для демо это сценарий: регистрация преподавателем, «ждёт допуска», допуск демо-администратором.
- Межфакультетские кафедры работают через выдачи: общий предмет вроде математики — выдачей факультета, курса факультета или курса на всех факультетах, а не десятком отдельных групп.
- Выдача курса не устаревает: со сменой учебного года она переходит на новый набор.

### Отрицательные

- При `off` или вне списка преподаватель не работает, пока администратор не рассмотрит заявку; без U13 допускать некому, остаются демо-преподаватели.
- Смена кафедры, снятие выдачи или смена учебного года меняет доступ сразу; преподаватель с выдачей курса теряет прошлогодние группы 1 сентября; уже созданные точки, активности и опросы остаются у автора: он принимает и возвращает работы, подтверждает участие и видит бюджет их групп, но новых ресурсов для недоступной группы не создаёт.
- Кафедра с формы — только часть заявки: её проверяет администратор при допуске, у преподавателя из списка её заменяет запись списка. Иначе выбором кафедры можно было бы получить доступ к чужому факультету.
- Ещё три таблицы (список, допуск, выдачи) и экраны админки (U13).

## Рассмотренные альтернативы

- Закрытый стенд с открытой саморегистрацией и принятым риском — отклонено: стенд будет на сервере (U22).
- Ручной допуск каждого преподавателя администратором — принят частично: только когда почта не проверена или её нет в списке.
- Только список почт, при `off` регистрация преподавателем закрыта и аккаунт создаёт администратор — отклонено при ревью PR #4: локальный стенд и сервер без U15 не показывали бы регистрацию преподавателя из базовой части ТЗ.
- Только список почт без подтверждения email — отклонено: при `off` любой, кто знает email из списка, занял бы аккаунт преподавателя.
- Жёсткое ограничение факультетом кафедры — отклонено: кафедры ведут занятия на других факультетах.

## Проверка

Тесты U5 (регистрация без допуска, пустой `TeacherScope`, `TeacherScope` допущенного), U15 (автодопуск по списку при `required`), U7, U9, U11, U16, U17 (403 вне доступных групп), U13 (заявки: допуск и отклонение; импорт списка, выдача и снятие группы, факультета, курса факультета и курса на всех факультетах). Это запланированные проверки, а не выполненные.
