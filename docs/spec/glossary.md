# Глоссарий

Единые имена доменных понятий. Код, API, UI-тексты и спека используют только эти термины; синонимы не вводим. Колонка «В коде» — имя типа/поля в backend и frontend.

## Люди и структура

| Термин | В коде | Определение |
|---|---|---|
| Роль | `Role` | `STUDENT`, `TEACHER`, `ADMIN`. У пользователя ровно одна роль. |
| Факультет | `Faculty` | Справочник. Группа принадлежит одному факультету. |
| Учебная группа | `StudyGroup` | Справочник. Не `Group` — слово занято в SQL и в Spring Security. |
| Кафедра | `Department` | Справочник. Принадлежит одному факультету. Преподаватель принадлежит одной кафедре; она задаётся записью списка преподавателей. |
| Членство в группе | `GroupMembership` | Связь студента с группой. Состояния: `PENDING` (ждёт подтверждения) и `ACTIVE`. Назначения и баллы активности получает только студент с `ACTIVE`-членством; стартовые 1000 АР и начисление семестра от членства не зависят. Время активации хранится. |
| Староста | `GroupHead` | Студент с правом подтверждать членство в своей группе. Назначает администратор. |
| Список преподавателей | `TeacherAllowlist` | Email и кафедра, с которыми разрешена регистрация с ролью `TEACHER`. Ведёт администратор; сравнение без учёта регистра. |
| Выдача доступа | `TeacherGrant` | Что администратор открыл преподавателю сверх факультета его кафедры: группа (`GROUP`), весь факультет (`FACULTY`), курс факультета (`FACULTY_COURSE`) или курс на всех факультетах (`COURSE`). |
| Курс группы | вычисляется из `StudyGroup.admissionYear` | Учебный год сейчас − год набора + 1; учебный год начинается 1 сентября по Europe/Moscow. Допустимы 1–6; группы вне диапазона под выдачи курса не попадают. |
| Доступные группы | `TeacherScope` | Группы факультета кафедры преподавателя плюс группы всех его выдач доступа. Только для них преподаватель создаёт точки, активности и опросы и видит рейтинги, бюджеты и аналитику. |

## Валюты и учёт

| Термин | В коде | Определение |
|---|---|---|
| Академический рейтинг, АР | `Currency.AR` | Целое число в диапазоне 0…1000. Уменьшается штрафами, растёт начислением семестра. |
| Баллы учебной активности, БУА | `Currency.BUA` | Неубывающая сумма баллов за учебные активности. |
| Баллы общественной активности, БОА | `Currency.BOA` | Неубывающая сумма баллов за общественные активности. |
| Журнал проводок | `Ledger` | Неизменяемый журнал всех изменений всех валют. Источник правды. |
| Проводка | `LedgerEntry` | Одна запись журнала: студент, валюта, знаковая сумма, вид, источник, автор, время, ключ идемпотентности. Нулевых проводок не бывает. |
| Вид проводки | `EntryKind` | `INITIAL` (стартовые 1000 АР), `SEMESTER_ACCRUAL`, `PENALTY`, `ACTIVITY_AWARD`. |
| Ключ идемпотентности | `idempotencyKey` | Уникальная строка, которая делает повторную запись того же события невозможной. |
| Баланс | `Balance` | Снимок суммы проводок по паре (студент, валюта). Обновляется в той же транзакции, что и проводка. |
| Инвариант баланса | — | Баланс равен сумме проводок по той же паре. |

## Академический рейтинг

| Термин | В коде | Определение |
|---|---|---|
| Контрольная точка | `Checkpoint` | Задача преподавателя для одной или нескольких групп: название, описание, дедлайн, стоимость. В UI — «задача». |
| Стоимость точки | `Checkpoint.cost` | Максимум АР, который можно списать с одного студента по этой точке. |
| Назначение | `Assignment` | Пара (контрольная точка, студент). Хранит состояние и сумму уже списанных штрафов. |
| Состояние назначения | `AssignmentState` | Хранимое: `OPEN` (работа не сдана или возвращена), `SUBMITTED`, `ACCEPTED`. |
| Статус назначения | `AssignmentStatus` | Вычисляемый для показа: «В процессе», «Сдано на проверку», «Просрочено», «Принято». Получается из состояния, дедлайна и текущего времени и в базе не хранится. |
| Сдача | `Submission` | Ссылка или файл, приложенные студентом при сдаче. |
| Возврат на доработку | `return` | Перевод назначения из `SUBMITTED` в `OPEN` с комментарием. |
| Штраф | `Penalty` | Проводка `PENALTY`: списание АР за просрочку. |
| Шаг штрафа | `Checkpoint.penaltyStep` | Номинальный размер одного списания. Копируется в точку из `Settings.penaltyStep` при создании (по умолчанию 20 АР). |
| Интервал штрафа | `Checkpoint.penaltyInterval` | Длина слота. Копируется в точку из `Settings.penaltyInterval` при создании (по умолчанию 1 минута). |
| Слот штрафа | `PenaltySlot` | Номер интервала после дедлайна: `n = floor((now − deadline) / interval)` при `now > deadline`. За каждый слот по назначению списывается не больше одного штрафа; слот с нулевой суммой тоже считается обработанным. |
| Семестр | `Semester` | Период с датой начала. С началом семестра всем студентам начисляется АР. |
| Начисление семестра | `SemesterAccrual` | Проводка `+N` АР, срезанная так, чтобы рейтинг не превысил 1000. Факт обработки пары (семестр, студент) хранится, даже если начислено 0. |

## Активности и ленты

| Термин | В коде | Определение |
|---|---|---|
| Активность | `Activity` | Мероприятие с типом `ACADEMIC` (даёт БУА) или `SOCIAL` (даёт БОА), целевыми группами, временем начала (`Activity.startsAt`) и максимумом баллов. |
| Запись на активность | `Enrollment` | Предварительная запись студента на `SOCIAL`-активность. Баллы за неё получают только записавшиеся. |
| Подтверждение участия | `ParticipationConfirmation` | Отметка преподавателем участника и уровня участия после времени начала активности. |
| Уровень участия | `ParticipationLevel` | 25, 50, 75 или 100 %. Студент получает соответствующую долю максимума. |
| Бюджет преподавателя | `TeacherBudget` | Лимит баллов на пару (преподаватель, группа) за календарный месяц по Europe/Moscow, общий для БУА и БОА. |
| Лента наград | `AwardsFeed` | Публичная лента проводок `ACTIVITY_AWARD`, новые сверху. |
| Персональная лента | `PersonalFeed` | Лента событий, адресованных конкретному пользователю. |
| Событие пользователя | `UserEvent` | Запись персональной ленты: получатель, тип, текст, время. |

## Опросы

| Термин | В коде | Определение |
|---|---|---|
| Опрос | `Poll` | Название, описание, дата окончания, целевые группы, признак анонимности. |
| Вопрос | `PollQuestion` | Тип `SINGLE` или `MULTIPLE`, список вариантов. |
| Голос | `Vote` | Выбранные варианты. В анонимном опросе голос не хранит автора. |
| Факт участия | `PollParticipation` | Отметка «пользователь проголосовал». Запрещает голосовать повторно и не раскрывает выбор через API и прикладную схему. |

## Запуск

| Термин | В коде | Определение |
|---|---|---|
| Режим запуска | профиль `demo` / `prod` | `demo` — синтетический сид, база и файлы пересоздаются при каждом запуске; `prod` — без сида, данные сохраняются. |
| Временный пароль | `TemporaryPassword` | Пароль, который выставил студенту преподаватель доступной группы, а студенту или преподавателю — администратор; при следующем входе пользователь обязан его сменить (R49). |
| Подтверждение email стенда | `campus.mail.email-verification`: `required` / `off` | Явная настройка без значения по умолчанию. `off` — подтверждение выключено, аккаунт активен сразу; остальные письма уходят, если SMTP настроен; без SMTP импортированному студенту временный пароль выставляет преподаватель или администратор (R49); допустимо в любом режиме. `required` — нужен SMTP-провайдер. |
