## Product Contract

### Summary

Четыре файла `e2e/tests/base/*.spec.ts` по разделу 8 тест-плана, каждый тест на проектах 360 и 1280; общий модуль фикстур для регистрации, входа и API-подготовки; тест-план обновлён под шаг штрафа 4 АР и под допуск преподавателя через backend U13.

### Правила

| № | Правило | Источник |
|---|---|---|
| П1 | Каждый тест — сценарий тест-плана со стабильным ID в названии; проверяет то, что видит пользователь (роли, подписи, тексты), подготовка данных — через API | `e2e/AGENTS.md`, тест-план §3 |
| П2 | Тесты независимы: свои пользователи (уникальный email на прогон), свои точки и активности; демо-история сида не используется как ожидание, кроме демо-администратора для допуска | тест-план §3, `e2e/AGENTS.md` |
| П3 | Преподаватель для теста — регистрируется и допускается администратором через `POST /api/v1/admin/teachers/{id}/approval` (U13); студенты — регистрация в группах факультета кафедры | U13 backend, R2 |
| П4 | Штраф: шаг 4 АР, интервал e2e 4 с; ожидания — `expect.poll` с запасом в несколько интервалов, без `waitForTimeout`; стоимость точки в PEN — 12 (3 слота до потолка) | тест-план §8, KTD1 правок UI |
| П5 | Без `force`, без CSS-селекторов, если есть роль или подпись; без ретраев | `e2e/AGENTS.md` |

## Planning Contract

### Key Technical Decisions

- KTD1. **Фикстуры** — `e2e/tests/base/support.ts`: `api` (контекст `request` с CSRF и сессией), `registerStudent(group)`, `registerTeacher(department)`, `approveTeacher(id)` (демо-админ), `login(page, user)`, создание точки, сдача, возврат, активность и подтверждение через API; уникальный префикс email на прогон.
- KTD2. **Время** — дедлайн и начало активности ставятся на несколько секунд вперёд от времени сервера, ожидание наступления — опросом API, а не сном.
- KTD3. **Тест-план** — PEN-01…03 пересчитаны под шаг 4 (потолок 12 = 3 слота), REG-02 — с допуском через API, матрица «требование → тест» и раздел 9 обновлены итогами прогона.
- KTD4. **Плавающий тест 33-2** — причина: запрос предыдущего теста уходит в сеть после `server.close()` (`ECONNREFUSED :3000`). Чинится жизненным циклом MSW файла и ожиданием прямых `api.GET` в `finish` при очистке; проверка — 30 прогонов файла подряд без падений.

## Implementation Units

### U1. Плавающий фронт-тест

- **Files:** `frontend/src/features/auth/review-fixes.test.tsx` (и при необходимости тест-хелперы).
- **Test scenarios:** 30 прогонов файла подряд — 30/30; полный `npm --prefix frontend run check` зелёный.

### U2. Фикстуры и регистрация

- **Files:** `e2e/tests/base/support.ts`, `e2e/tests/base/registration.spec.ts`.
- **Test scenarios:** REG-01 (+ негативные: пароль < 8, занятый email, группа другого факультета — ошибка под полем), REG-02 (плашка ожидания, нет групп → допуск админом → группы появились; email из списка преподавателей не регистрируется студентом), AUTH-01 (одинаковая ошибка неверного пароля и email, без входа → `/login`, API 401, после выхода сессии нет, POST без CSRF — 403).

### U3. Точки и штраф

- **Files:** `e2e/tests/base/checkpoint-penalty.spec.ts`.
- **Test scenarios:** CP-01 (создание через UI, назначения у студентов группы, шаг 4), CP-02 (сдача ссылкой до дедлайна, «Сдано на проверку», новая версия в истории; отзыв до дедлайна), PEN-01 (после дедлайна −4 за слот до 12, АР 988, «Просрочено», «Списано 12 из 12 АР»), PEN-02 (сдача после слота — списания прекращаются), PEN-03 (возврат с комментарием — комментарий виден, штраф продолжается до общего потолка), CP-03 (приём пачкой: сданная — «Принято», несданная — пропуск с причиной).

### U4. Активности и бюджет

- **Files:** `e2e/tests/base/activity-budget.spec.ts`.
- **Test scenarios:** ACT-01 (создание, видна студенту группы), ACT-02 (запись и отмена на `SOCIAL` до начала; закрыта после начала), ACT-03 (подтверждение 50 % от 75 = 38 БОА, предпросмотр, запись в истории студента), BUD-01 (остаток уменьшается на сумму; сверх остатка — отказ целиком с текстом нехватки).

### U5. Профиль, лента, рейтинг

- **Files:** `e2e/tests/base/feed.spec.ts`.
- **Test scenarios:** PRF-01 (свой профиль: балансы, история в формате R6, задачи; чужой — без перехода к сдаче), FEED-01 (начисление появилось в ленте у другого пользователя первым), RAT-01 (рейтинг группы по АР/БУА/БОА у преподавателя; студенту — «Нет доступа»).
