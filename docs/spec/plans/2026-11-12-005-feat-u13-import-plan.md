# Дать администратору импорт групп, студентов и списка преподавателей - Plan

**Target repo:** campus-rating

## Goal Capsule

- **Objective:** администратор загружает группы, студентов и список преподавателей из CSV или XLSX и получает отчёт по строкам.
- **Authority:** Requirements → Acceptance Examples → Key Decisions → исходное ТЗ (модуль 8), мастер-план (R2, R25, R31, R48, U13) → Sources.
- **Open blockers:** нет.

## Product Contract

### Summary

Экран «Импорт» (`/admin/import`) с тремя видами импорта, отчётом по строкам и списком преподавателей с удалением записи. Импортированный студент создаётся как при регистрации. При настроенном SMTP студенту уходит письмо со ссылкой установки пароля (`/password/set/:token`).

### Problem Frame

- **Кто:** администратор стенда.
- **Сейчас:** группы — через «Справочники» по одной, студенты — только саморегистрацией, список преподавателей (`teacher_allowlist`) — только SQL и сид.
- **Зачем:** исходное ТЗ, модуль 8: «Импорт групп и студентов из CSV или Excel»; мастер-R25 добавляет список преподавателей.
- **Риски данных:** импорт создаёт пользователей и проводки `INITIAL` (1000 АР) — удалить их нельзя; поэтому повторный импорт не должен создавать дублей.

### Requirements

**Файлы**

- R1. Три вида импорта, выбор на экране: «Группы», «Студенты», «Список преподавателей». Колонки (первая строка — заголовок с этими именами в этом порядке): группы — `faculty_code,group_code,group_name,admission_year`; студенты — `email,full_name,faculty_code,group_code`; список преподавателей — `email,department_code` (источник: мастер-план U13).
- R2. Форматы: CSV с разделителем `,` или `;` и кодировкой UTF-8 (с BOM или без) или Windows-1251; XLSX — первый лист, та же структура. Кодировка: файл, корректный как UTF-8, читается как UTF-8, иначе — как Windows-1251. Разделитель: тот из `,` и `;`, по которому заголовок делится ровно на колонки R1; иначе — R3 «Не удалось прочитать файл…». Значения в CSV — по RFC 4180: в двойных кавычках могут быть разделитель, кавычка (`""`) и перенос строки (источник: пользователь, интервью; правила определения — предложение).
- R3. Предел: файл до 5 МБ (5 × 1024 × 1024 байт загружаемого файла) и до 5000 строк данных. Строка данных — запись после заголовка (запись CSV с переносом внутри кавычек — одна строка); полностью пустые строки пропускаются и не считаются. Больше — «Файл слишком большой: до 5 МБ и 5000 строк», ничего не создаётся. Нечитаемый файл или неверный заголовок — «Не удалось прочитать файл: проверьте формат и заголовок», ничего не создаётся (источник: пользователь, интервью; тексты — предложение).

**Обработка строк**

- R4. Каждая строка проверяется отдельно по порядку файла и учитывает строки, принятые выше в том же файле. Валидные строки сохраняются одной транзакцией; сбой сохранения — ничего не создано, «Импорт не выполнен, попробуйте ещё раз». Строка с другим числом колонок — отклонена «неверное число колонок»; пустое обязательное значение — «пустое значение <колонка>». При нескольких ошибках в строке показывается первая по порядку колонок. Строка, совпадающая с существующей записью (или с принятой строкой выше) по всем колонкам файла после обрезки пробелов, — «уже есть», пропускается (источник: мастер-план U13; правила дублей и порядка ошибок — предложение).
- R5. Группы: `faculty_code` должен существовать — иначе «факультет не найден»; `group_code` уникален — тот же код с другим факультетом, названием или годом — «код группы занят»; длины и символы кода и названия — как при создании группы в «Справочниках»; `admission_year` — целое 2000…2100 — иначе «неверный год набора» (источник: мастер-план U13; правила кода и года — предложение).
- R6. Студенты: создаются как при регистрации (мастер-R1, R8): роль «студент», группа из файла, членство `ACTIVE` (источник — администратор), 1000 АР проводкой `INITIAL`. Пароля в файле нет. Студент «уже есть», если email принадлежит студенту с тем же ФИО и той же группой. Причины отказа: «факультет не найден», «группа не найдена», «группа другого факультета», «email занят» (email у другого пользователя или у студента с другим ФИО или группой), «email из списка преподавателей», «неверный email», «пустое ФИО» (источник: мастер-план U13, R2; формулировки — предложение там, где их нет в мастер-плане).
- R7. Пароль импортированного студента: если SMTP настроен (заданы настройки почты стенда, мастер-R48), письмо со ссылкой `/password/set/:token` отправляется после сохранения импорта; сбой отправки не меняет отчёт и созданных студентов, пишется в лог. Без SMTP письмо не отправляется, пароль выставляет преподаватель или администратор временным паролем (файл `006`). Подтверждение email `required` без SMTP невозможно: backend не стартует (мастер-R48) (источник: мастер-R48, R31, U13).
- R8. Ссылка установки пароля: действует 24 часа, расходуется при успешной установке пароля (открытие формы её не расходует); выставление временного пароля (файл `006`) делает неиспользованные ссылки недействительными — «Ссылка уже использована». Установка задаёт пароль (правила пароля — как при регистрации) и подтверждает email; использованная — «Ссылка уже использована», истёкшая — «Ссылка устарела. Попросите преподавателя или администратора выставить временный пароль» (источник: мастер-план U13, R31; тексты — предложение).
- R9. Список преподавателей: строка добавляет запись «email + кафедра»; `department_code` должен существовать — иначе «кафедра не найдена»; email уже в списке с той же кафедрой — «уже есть», с другой — «email уже в списке с другой кафедрой»; email зарегистрированного студента — «email занят студентом», администратора — «email занят администратором»; неверный email — «неверный email». Импорт только пополняет список (источник: мастер-план U13, R2).

**Отчёт и список**

- R10. После импорта — отчёт: «Создано: X · Пропущено (уже есть): Y · Отклонено: Z» и таблица отклонённых строк: номер строки (заголовок — 1, далее строки данных по R3), ключ строки (группы — `group_code`, студенты и список преподавателей — `email`), причина (источник: мастер-R25, U13).
- R11. На экране «Импорт» — раздел «Список преподавателей»: email, кафедра, «Зарегистрирован» (да/нет); по email без регистрации — кнопка «Удалить» с подтверждением «Удалить <email> из списка преподавателей?». Запись зарегистрированного преподавателя не удаляется: кнопки нет, API отклоняет «Преподаватель уже зарегистрирован — удалить нельзя» (источник: мастер-план U13 — «удаление — вручную на экране «Импорт»»; ограничение — предложение).

**Доступ**

- R12. Только администратор; остальным — «Нет доступа» и `403` (источник: мастер-R3, R24).

### Key Decisions

- **Автоопределение формата CSV** (session-settled: user-directed — chosen over «только UTF-8 и запятая»: CSV из Excel на русской Windows загружается без конвертации). Governs R2, R3.
- **Пределы 5 МБ и 5000 строк** (session-settled: user-approved — chosen over «без ограничений»: импорт идёт одной операцией). Governs R3.

### Acceptance Examples

- AE1. **Covers R1, R2, R6, R10.** Дано: CSV студентов в Windows-1251 через `;`, 10 строк, у строк 3 и 7 — `faculty_code` «XXX». Когда: импорт «Студенты». Строка 2 файла: `ivanov@student.campus.test;Иванов Иван Иванович;ФИТ;ИВТ-21`. Тогда: «Создано: 8 · Пропущено (уже есть): 0 · Отклонено: 2», в таблице строки 4 и 8 файла (заголовок — 1) с причиной «факультет не найден»; ФИО созданных — без искажений; у созданных 1000 АР и членство подтверждено.
- AE2. **Covers R2.** Дано: тот же набор в XLSX. Тогда: тот же отчёт.
- AE3. **Covers R4.** Когда: повторный импорт того же файла. Тогда: «Создано: 0 · Пропущено (уже есть): 8 · Отклонено: 2», новых проводок `INITIAL` нет.
- AE4. **Covers R6.** Дано: строка с email существующего студента и другим ФИО. Тогда: отклонена «email занят».
- AE5. **Covers R3.** Дано: файл 6 МБ; файл с 5001 строкой данных; файл с заголовком `mail,name,…`. Тогда: «Файл слишком большой: до 5 МБ и 5000 строк» в первых двух случаях, «Не удалось прочитать файл: проверьте формат и заголовок» в третьем; ничего не создано.
- AE6. **Covers R5.** Дано: CSV групп из 3 строк: новая группа, повтор существующей «ИВТ-21» с теми же данными, «ИВТ-21» с другим названием. Тогда: создано 1, пропущено 1, отклонено 1 «код группы занят».
- AE7. **Covers R7.** Дано: SMTP не настроен. Тогда: импортированный студент не может войти до временного пароля; писем нет; отчёт не меняется.
- AE8. **Covers R7, R8.** Дано: SMTP настроен. Тогда: студенту приходит письмо со ссылкой; переход и ввод пароля «secret-pass-1» — вход проходит, email подтверждён; повторный переход — «Ссылка уже использована»; второму студенту из того же импорта: переход через 25 часов — «Ссылка устарела. Попросите преподавателя или администратора выставить временный пароль»; третьему: после временного пароля из `003` переход по ссылке — «Ссылка уже использована».
- AE9. **Covers R9, R11.** Дано: список преподавателей из 3 строк: новая, повтор с той же кафедрой, email студента Смирновой. Тогда: создано 1, пропущено 1, отклонено «email занят студентом». После импорта регистрация студентом с новым email — отказ (мастер-R2). Удаление записи без регистрации — пропадает из списка; у зарегистрированного Петрова кнопки «Удалить» нет.
- AE10. **Covers R12.** Дано: вход преподавателем. Тогда: `/admin/import` — «Нет доступа», API импорта и удаления — `403`.
- AE11. **Covers R2, R4.** Дано: CSV студентов в UTF-8 через `,`, строка 2 — `"petrova@student.campus.test","Петрова, Мария",ФИТ,ИВТ-21`, строка 3 повторяет строку 2, строка 4 — с лишней колонкой. Тогда: создано 1, пропущено 1, отклонено 1 «неверное число колонок»; ФИО «Петрова, Мария».

### Success Criteria

- Набор групп и студентов курса (сотни строк) загружается за один импорт; повторная загрузка того же файла ничего не создаёт.

### Scope Boundaries

Не входит:
- Импорт преподавателей как пользователей (только список «email + кафедра»).
- Удаление и изменение пользователей импортом.
- Фоновая обработка файла и импорт больше 5000 строк.
