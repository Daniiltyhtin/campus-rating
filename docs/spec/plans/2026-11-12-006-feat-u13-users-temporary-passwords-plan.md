# Дать администратору список пользователей и временные пароли - Plan

**Target repo:** campus-rating

## Goal Capsule

- **Objective:** администратор находит любого пользователя и выставляет временный пароль студенту или преподавателю; преподаватель — студенту доступной группы (мастер-R49).
- **Authority:** Requirements → Acceptance Examples → Key Decisions → мастер-план (R3, R49, U13), карта экранов → Sources.
- **Open blockers:** нет.

---

## Product Contract

### Summary

Экран администратора `/admin/users` (поиск, фильтр по роли, «Загрузить ещё») и экран преподавателя `/groups/:id/students`. Из обоих выставляется временный пароль: система генерирует его, показывает один раз, пользователь меняет его при входе, остальные его сессии завершаются, действие записывается, в своём профиле пользователь видит «Пароль выставлен».

### Problem Frame

- **Кто:** администратор; преподаватель с доступом к группе.
- **Сейчас:** смена пароля при входе (`must_change_password`) работает только для первого администратора; выставить временный пароль нельзя; при выключенной почте забытый пароль не восстановить.
- **Зачем:** мастер-R49 и карта экранов (`/groups/:id/students`, карточки в `/admin/*`); на стенде жюри SMTP нет.
- **Риски данных:** временный пароль даёт вход в чужой аккаунт до смены. Пароль хранится только хешем и не пишется в логи; открытым текстом он есть только в ответе операции выставления.

### Requirements

**Пользователи (`/admin/users`)**

- R1. Список всех пользователей: колонки — ФИО (ссылка на профиль `/users/:id`), email, роль («Студент», «Преподаватель», «Администратор»), группа (у студента) или кафедра (у преподавателя), «Пароль выставлен» (дата по Москве последнего временного пароля или пусто) (источник: пользователь, интервью).
- R2. Поиск — подстрока ФИО или email без учёта регистра, применяется от 2 символов после обрезки пробелов (короче — условие поиска не применяется, остальное как обычно); фильтр «Роль»: «Все», «Студенты», «Преподаватели», «Администраторы» (по умолчанию «Все») (источник: пользователь, интервью).
- R3. Сортировка по ФИО, затем по id; по 50 строк; кнопка «Загрузить ещё», пока есть следующая страница. Смена поиска или роли показывает первую страницу нового результата, загруженные строки сбрасываются. Нет совпадений — «Никого не нашли» (источник: пользователь, интервью; текст пустого состояния — предложение).
- R4. В строке студента и преподавателя — кнопка «Выставить временный пароль»; у администратора кнопки нет (источник: мастер-R49).

**Студенты группы (`/groups/:id/students`)**

- R5. Преподавателю, у которого группа в доступных (группы факультета его кафедры и выдачи администратора — те же, что на экране «Группы и бюджет»), — список студентов, чьё членство в группе `ACTIVE` («подтверждено») или `PENDING` («ждёт подтверждения»): ФИО (ссылка на профиль `/users/:id`), email, членство, «Пароль выставлен» (дата или пусто), кнопка «Выставить временный пароль»; сортировка по ФИО. Ссылка «Студенты» — у каждой группы на экране «Группы и бюджет». Группа вне доступных — «Нет доступа» (источник: мастер-R49, карта экранов; ссылка и колонка членства — предложение).

**Временный пароль**

- R6. Подтверждение: «Выставить временный пароль для <ФИО>? Пользователь сменит его при входе, все его сессии завершатся.», кнопки «Выставить» и «Отмена» (источник: мастер-R49; текст — предложение).
- R7. Пароль генерирует система: 12 символов из латинских букв и цифр без `0`, `O`, `1`, `l`, `I`. Он есть только в ответе операции и в открытом диалоге; после закрытия диалога его не получить ни с экрана, ни через API. Диалог — с кнопкой «Скопировать» и текстом «Пароль выставлен, <студент|преподаватель> сменит его при входе» (источник: пользователь, интервью; карта экранов — текст итога).
- R8. После выставления: все сессии пользователя завершаются; при следующем входе он обязан сменить пароль на отличный от временного; до смены остальные запросы отклоняются `PASSWORD_CHANGE_REQUIRED` — набор разрешённых запросов как сейчас у первого администратора (смена пароля, `GET /auth/me`, CSRF, выход). Неиспользованные ссылки установки пароля из письма (файл `005`) перестают действовать (источник: мастер-R49; код, как сейчас — `PasswordChangeFilter`).
- R9. Каждое выставление записывается (кто, кому, когда), история хранится; на экранах показывается последнее. В своём профиле пользователь видит «Пароль выставлен: <ФИО того, кто выставил>, <дата и время по Москве>»; в чужом профиле строки нет (источник: мастер-R49).
- R10. Кому можно: администратор — любому студенту и преподавателю; преподаватель — студенту доступной группы; иначе — `403` и «Нет доступа» (источник: мастер-R49, R3).
- R11. Работает в обоих режимах подтверждения email (`required`, `off`). При `required` временный пароль email не подтверждает: для входа нужны и подтверждённый email, и смена пароля; `required` без SMTP не бывает — backend не стартует (источник: мастер-R31, R48, R49).

### Key Decisions

- **Отдельный экран `/admin/users`** (session-settled: user-directed — chosen over «кнопка в профиле» и «профиль + карточка преподавателя»: администратор находит любого пользователя поиском). Governs R1–R4.
- **Экран преподавателя входит в задачу** (session-settled: user-approved — chosen over «только администратор»: без почты это единственный способ сбросить пароль студенту без администратора). Governs R5, R10.
- **«Загрузить ещё» вместо номеров страниц** (session-settled: user-approved — chosen over «весь список» и «нумерованные страницы»: единообразно с лентами, курсор не съезжает при добавлении пользователей). Governs R3.

### Acceptance Examples

- AE1. **Covers R1, R2, R3.** Дано: демо-стенд. Когда: администратор вводит «смир». Тогда: строка «Смирнова Анна Олеговна · smirnova@student.campus.test · Студент · ИВТ-21». Когда: «с» (1 символ). Тогда: поиск не применяется, показан весь список. Когда: роль «Преподаватели». Тогда: только Петров и Волков. Когда: «zzz». Тогда: «Никого не нашли».
- AE2. **Covers R3.** Дано: к стенду добавлено 120 студентов «Тест 001» … «Тест 120» (всего больше 120 пользователей); поиск «тест». Тогда: 50 строк «Тест 001»…«Тест 050» и «Загрузить ещё»; после двух нажатий — 120, кнопки нет; дублей нет. Когда: роль «Преподаватели». Тогда: список с первой страницы, «Никого не нашли». Когда: поиск «т» (1 символ). Тогда: первые 50 строк всех пользователей.
- AE3. **Covers R4, R6, R7, R8, R9.** Когда: администратор — «Выставить временный пароль» у Смирновой → «Выставить». Тогда: диалог с паролем из 12 символов и «Пароль выставлен, студент сменит его при входе». Открытая ранее сессия Смирновой при следующем запросе — на вход. Вход Смирновой с временным паролем — сразу экран смены пароля, другие разделы закрыты; после смены — профиль со строкой «Пароль выставлен: Администратор Демо, <дата>»; в профиле Смирновой под Петровым этой строки нет; в списке пользователей у Смирновой дата в «Пароль выставлен».
- AE4. **Covers R4.** Тогда: у строки «Администратор Демо» кнопки нет.
- AE5. **Covers R5, R10.** Дано: Петров, группы ИВТ-21 и ИВТ-22 доступны. Когда: «Группы и бюджет» → «Студенты» у ИВТ-21. Тогда: список студентов ИВТ-21 по ФИО, у Орлова «ждёт подтверждения». Дано: администратор создал группу «ЭК-11» факультета ЭФ, выдачи Петрову нет. Когда: Петров открывает `/groups/<id ЭК-11>/students`. Тогда: «Нет доступа». Когда: Петров выставляет пароль Смирновой (ИВТ-21) и нажимает «Отмена» в подтверждении. Тогда: пароль не изменён, строки «Пароль выставлен» нет.
- AE6. **Covers R10.** Когда: преподаватель запросом API выставляет пароль преподавателю или студенту недоступной группы. Тогда: `403`, пароль не изменён.
- AE7. **Covers R7.** Когда: генератор паролей вызван 100 раз (модульный тест). Тогда: длина каждого 12, символов `0`, `O`, `1`, `l`, `I` нет. Когда: диалог с паролем закрыт. Тогда: ни на экране, ни в ответах API пароль не виден.
- AE8. **Covers R10.** Дано: вход студентом. Тогда: `/admin/users` и `/groups/<id>/students` — «Нет доступа», API — `403`.
- AE9. **Covers R4, R8, R10.** Когда: администратор выставляет пароль преподавателю Волкову. Тогда: диалог «Пароль выставлен, преподаватель сменит его при входе»; Волков входит, новый пароль, равный временному, отклоняется; до смены любой другой запрос API (например, лента) — `PASSWORD_CHANGE_REQUIRED`, выход работает.
- AE10. **Covers R11.** Дано: стенд с `required` и SMTP, студент с подтверждённым email. Когда: временный пароль и вход. Тогда: экран смены пароля, после смены — вход. Студент с неподтверждённым email после смены пароля видит «Отправить ссылку подтверждения».

### Success Criteria

- На стенде без SMTP забытый пароль студента восстанавливает его преподаватель операцией «Выставить временный пароль» (кнопка и подтверждение), без администратора и SQL.

### Scope Boundaries

Не входит:
- Изменение данных пользователя (ФИО, email, группы) из списка.
- Блокировка и удаление пользователей.
- Временный пароль администратору.
