# Показать администратору материалы сдачи - Plan

**Target repo:** campus-rating

## Goal Capsule

- **Objective:** администратор из профиля студента открывает материалы сдачи задачи — только чтение.
- **Authority:** Requirements → Acceptance Examples → мастер-план (R5, R24), карта экранов → Sources.
- **Open blockers:** нет.

## Product Contract

### Summary

Экран `/admin/submissions/:assignmentId`: точка, студент, статус, все версии сдач со ссылками и файлами, замечания возврата. Без действий преподавателя и студента. Backend чтения уже пускает администратора (`GET /assignments/{id}`).

### Problem Frame

- **Кто:** администратор.
- **Сейчас:** в профиле студента у администратора задачи с `assignmentId` (вид `ADMIN`), но экрана `/admin/submissions/:id` нет — ссылка ведёт на заглушку. API `GET /assignments/{id}` и скачивание файлов версий администратору уже разрешены.
- **Зачем:** мастер-R24 — «просматривает материалы сдачи (только чтение)»; мастер-R5 — ссылка «Материалы сдачи» в профиле для администратора.
- **Риски данных:** нет.

### Requirements

- R1. В профиле студента у администратора у каждой задачи — ссылка «Материалы сдачи» на `/admin/submissions/<assignmentId>` (источник: мастер-R5, карта экранов).
- R2. Экран показывает те же данные и в тех же формулировках, что экран задачи студента `/tasks/:id` (`TaskPage.tsx`) для этого назначения: заголовок — название точки (*точка* — контрольная точка преподавателя); строка «<ФИО студента> · <группа>»; дедлайн; пилюля статуса; «Списано X из Y АР» (X — списано штрафом, Y — бюджет точки, как у студента); история сдач — все версии от последней отправленной к первой: дата отправки, ссылка или файл (у версии ровно одно из двух; файл скачивается с исходным именем), у отозванной — «Отозвана студентом · <дата отзыва>», у возвращённой — «Замечание преподавателя · <автор> · <дата возврата>» и текст. Даты — `ДД.ММ.ГГГГ ЧЧ:ММ` по Москве. Отличие от экрана студента: все замечания показаны сразу, без раскрытия (источник: мастер-R24, карта экранов; вид — экран задачи после правок UI).
- R3. Кнопок сдачи, отзыва, приёма и возврата нет. API сдачи, отзыва, приёма и возврата отклоняет администратора кодом `403`; если сейчас не отклоняет — это часть задачи (источник: мастер-R24 — «только чтение»).
- R4. Нет сдач — «Сдач нет». Несуществующее назначение — «Не найдено» / «Проверьте адрес страницы.»; не администратор — «Нет доступа» / «Этот раздел недоступен для вашей роли.», в том числе для несуществующего назначения (роль проверяется первой) (источник: тексты экранов после правок UI).

### Acceptance Examples

- AE1. **Covers R1, R2.** Дано: демо-история, работа Лебедевой возвращена «Добавьте выводы». Когда: администратор — профиль Лебедевой → «Материалы сдачи» у лабораторной. Тогда: заголовок «Лабораторная работа: анализ данных», «Лебедева … · ИВТ-21», история со ссылкой и развёрнутым «Замечание преподавателя · Петров П. П. · <дата>» и текстом «Добавьте выводы».
- AE2. **Covers R2.** Дано: версия-файл. Тогда: файл скачивается администратором с исходным именем.
- AE3. **Covers R3.** Тогда: на экране нет кнопок «Сдать работу», «Отозвать сдачу», «Принять», «Вернуть…».
- AE4. **Covers R4.** Дано: назначения 999999 нет. Когда: администратор открывает задачу без сдач; `/admin/submissions/999999`; преподаватель открывает `/admin/submissions/<id>` и `/admin/submissions/999999`. Тогда: «Сдач нет»; «Не найдено»; «Нет доступа» в обоих случаях.
- AE5. **Covers R2, R3.** Дано: студент сдал ссылку `https://example.org/v1`, отозвал, затем сдал файл `report.pdf`. Тогда: у администратора две версии — сверху `report.pdf`, ниже ссылка с «Отозвана студентом · <дата>»; `POST /api/v1/assignments/<id>/return` от администратора — `403`.

### Success Criteria

- Администратор видит по задаче всё, что видит на экране задачи студент (R2), не входя под студентом или преподавателем.

### Scope Boundaries

Не входит:
- Список всех сдач без привязки к профилю студента.
- Действия над сдачей.
