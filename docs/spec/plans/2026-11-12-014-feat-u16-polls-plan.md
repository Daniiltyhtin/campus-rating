# U16: опросы - Plan

## Goal Capsule

- **Цель.** Преподаватель создаёт опрос для доступных групп; студент целевой группы голосует один раз до окончания и после голоса видит статистику; автор видит детальную статистику, в неанонимном опросе — по студентам. Создание опроса и его завершение попадают в персональную ленту (U14).
- **Иерархия источников.** Мастер-план (U16, R3, R28, R29, R32–R35; KTD11, KTD14, KTD23) → `docs/spec/glossary.md` («Опросы») → `docs/spec/ux/screen-map.md` и `open-questions.md` (В4а, В5а) → план U14 `2026-11-12-009-feat-u14-personal-feed-plan.md` (как события попадают в ленту) → контракт после U0.
- **Профиль исполнения.** U0 (контракт) — отдельным коммитом до тестов. Приёмочные тесты U1–U5 пишет отдельная сессия `write-tests` до реализации; исполнитель (`implement-unit`) их не меняет и не коммитит.
- **Остановись и спроси, если:** нужно менять контракт сверх U0, схему анонимного голоса (KTD2), зависимость модулей вне диаграммы мастер-плана (`poll → identity`, `feed` слушает `poll`) или формат строки ленты сверх двух новых видов.

## Product Contract

### Правила

| № | Правило | Источник |
|---|---|---|
| П1 | Опрос: название (1–200), описание (0–2000), окончание (дата и время по Москве, строго в будущем), целевые группы (1+, без повторов, все из `TeacherScope` автора — иначе `403`, опрос и события не создаются), признак анонимности, 1–20 вопросов | R33, KTD23 |
| П2 | Вопрос: текст (1–500), тип `SINGLE` или `MULTIPLE`, 2–10 вариантов (текст 1–200, без повторов внутри вопроса после `trim`) | R33 |
| П3 | После создания опрос не меняется и не удаляется: голоса относятся к неизменным вопросам. Досрочного закрытия нет | решение плана, см. «Открытые решения» |
| П4 | Голосует студент с `ACTIVE`-членством в одной из целевых групп, до окончания, один раз. Ответ обязателен на каждый вопрос: `SINGLE` — ровно один вариант, `MULTIPLE` — один или больше; варианты — только этого вопроса. Повтор — `409 ALREADY_VOTED`; после окончания — `422 POLL_CLOSED`; `PENDING` или `REJECTED` — `422 MEMBERSHIP_NOT_ACTIVE`; студент не той группы — `403` | R32, R34 |
| П5 | Статистика для студента: по каждому варианту — число голосов и доля; число проголосовавших. Видна только после своего голоса, в том числе после окончания. Не голосовавший видит опрос без статистики | R34 |
| П6 | Автор видит статистику всегда и «проголосовали N из M» (M — студенты целевых групп с `ACTIVE` сейчас). В неанонимном опросе — ещё ответы по студентам (ФИО, группа, выбранные варианты). В анонимном детализации нет ни в каком виде | R35 |
| П7 | Опрос видят только автор и студенты целевых групп (любое состояние членства). Другой преподаватель и администратор — `403` на чтение опроса и ответов | R3, R35, В5а |
| П8 | Создание опроса — событие в ленте студентам целевых групп с `ACTIVE` на момент создания: «Новый опрос «<название>» · до <дата и время>». Завершение — событие автору: «Опрос «<название>» завершён · проголосовали N из M». Ссылка — `/polls/:id`. Повторная доставка дубля не даёт | R28, R29, U14 |
| П9 | В анонимном опросе связь «студент — выбор» отсутствует в прикладной схеме, ответах API и логах приложения. Защита от администратора БД с доступом к системным полям PostgreSQL не заявляется | R35, KTD14 |

### Acceptance Examples

Стенд demo, время — Москва.

- AE1. **Covers П1, П8.** В ИВТ-21 шесть студентов с `ACTIVE` и `PENDING`-Орлов. Петров создаёт анонимный опрос «Формат зачёта» для ИВТ-21 до 20.11.2026 18:00 с вопросом `SINGLE` «Когда удобнее?» (Утро, Вечер). У Смирновой на «Главной» — блок «Новые опросы» и событие ленты «Новый опрос «Формат зачёта» · до 20.11.2026 18:00»; у студентов ИВТ-22 и у `PENDING`-Орлова события нет.
- AE2. **Covers П4, П5.** Смирнова голосует «Вечер» → видит «Утро 0 (0 %), Вечер 1 (100 %), проголосовал 1». Повторный голос — `409 ALREADY_VOTED`. Кузнецов до голоса статистики не видит.
- AE3. **Covers П6, П9.** Автор анонимного «Формата зачёта» видит «проголосовали 1 из 6» и распределение; запрос ответов по студентам — `409 INVALID_STATE`. В неанонимном опросе автор видит «Смирнова Анна Олеговна · ИВТ-21 · Вечер».
- AE4. **Covers П7.** Другой допущенный преподаватель с доступом к ИВТ-21 (в тесте — из фикстуры) и администратор получают `403` на опрос Петрова.
- AE5. **Covers П8.** Наступило 20.11.2026 18:00 → у Петрова одно событие «Опрос «Формат зачёта» завершён · проголосовали 1 из 6»; голос после этого — `422 POLL_CLOSED`.

### Открытые решения (решены планом, проверить на ревью)

- Неизменяемость опроса и отсутствие досрочного закрытия (П3): иначе нужно правило для уже поданных голосов; ТЗ правку не требует.
- Не голосовавший студент статистику не видит и после окончания (П5): буква R34 «после голосования».
- Другой преподаватель не видит даже агрегат чужого опроса (П7): R3 «только свои опросы».

### Scope Boundaries

- Не входит: правка, удаление, досрочное закрытие, свободный текст в ответе, экспорт результатов, напоминание «опрос скоро закончится», email-уведомления (U18), ИИ-сводка ответов (U19).

## Planning Contract

### Key Technical Decisions

- KTD1. **Владелец — модуль `poll`.** `poll/api` (контроллер, DTO), `poll/domain` (чистые проверки создания и голоса: `PollDraft`, `Ballot`, `VoteValidation` — недопустимый голос невыразим после проверки), `poll/internal` (репозиторий на `JdbcClient`, сервисы, задание завершения). Доступные группы — `TeacherScope`, членство — `GroupMembers` из `identity`; своих правил доступа модуль не дублирует (KTD23).
- KTD2. **Анонимность — на уровне схемы (KTD14).** Changeset `backend/src/main/resources/db/changelog/poll/<ts>-poll.sql`: `poll`, `poll_group`, `poll_question`, `poll_option` со счётчиком `vote_count`, `poll_participation(poll_id, student_id, voted_at, unique(poll_id, student_id))`, `poll_named_choice(poll_id, option_id, student_id)` — только для неанонимных опросов. Голос анонимного опроса — только инкремент счётчиков вариантов в той же транзакции, что вставка участия: строки «голос» нет вовсе, поэтому нет ни ссылки на студента, ни id и времени, которые можно сопоставить с участием. Неанонимный — те же счётчики плюс строки `poll_named_choice`. Статистика читается из счётчиков для обоих видов. Требование мастер-сценария «в таблице голосов нет ссылки на пользователя» выполняется сильнее: таблицы голосов анонимного опроса нет.
- KTD3. **Однократность.** Уникальность `(poll_id, student_id)` в `poll_participation`; вставка первой, при конфликте — `409 ALREADY_VOTED`, счётчики не трогаются. Счётчики — `update … set vote_count = vote_count + 1` в одной транзакции.
- KTD4. **Логи.** Тело запроса голоса не логируется; ошибки валидации называют поле (`answers[0].optionIds`), но не id студента. Тест захватывает логи приложения при голосе на уровне `DEBUG` и ищет пару «id студента — id варианта».
- KTD5. **События (KTD11, по образцу U14).** `poll` публикует `PollCreated(pollId, title, endsAt, studentIds, occurredAt)` — получатели вычисляет издатель (`ACTIVE` целевых групп на момент создания) — и `PollClosed(pollId, title, authorId, voted, eligible, occurredAt)`. Завершение публикует задание `poll` раз в минуту: опросы с `ends_at <= now` и `closed_at is null` получают `closed_at` и событие в одной транзакции. `feed` добавляет виды `POLL_CREATED` и `POLL_CLOSED`, ключи `poll:{pollId}` и `pollClosed:{pollId}`; фронтенд собирает тексты по виду, как в U14.
- KTD6. **Ошибки.** В `shared.error.ProblemCode` и контракт — `ALREADY_VOTED` (409) и `POLL_CLOSED` (422); остальные — существующие (`VALIDATION_FAILED`, `FORBIDDEN`, `NOT_FOUND`, `INVALID_STATE`, `MEMBERSHIP_NOT_ACTIVE`).
- KTD7. **Экран и диаграмма.** Входы по `screen-map.md`: на «Главной» студента — блок «Новые опросы» (открытые, без голоса), у преподавателя — «Мои опросы» (открытые); шестого пункта меню нет. Результаты — горизонтальные полосы на CSS с числом и долей текстом рядом (читается без цвета), без библиотеки диаграмм; исполнитель следует скиллу `dataviz`.

### Контракт (U0)

| Операция | Роли | Запрос → ответ |
|---|---|---|
| `POST /api/v1/polls` (`createPoll`) | `TEACHER` | `{title, description, endsAt, groupIds, anonymous, questions:[{text, type, options:[text]}]}` → `201 Poll`; `400` по полю, `403` |
| `GET /api/v1/polls` (`listPolls`) | `TEACHER`, `STUDENT` | → `{items:[PollSummary]}`: у преподавателя — свои, у студента — опросы его группы; сначала открытые по окончанию возр., затем завершённые по окончанию убыв., затем id |
| `GET /api/v1/polls/{pollId}` (`getPoll`) | `TEACHER`, `STUDENT` | → `Poll` (вопросы, варианты, `open`, `voted`, `results: PollResults \| null`, у автора `eligible`); `403`, `404` |
| `POST /api/v1/polls/{pollId}/vote` (`votePoll`) | `STUDENT` | `{answers:[{questionId, optionIds}]}` → `200 PollResults`; `400`, `403`, `409 ALREADY_VOTED`, `422 POLL_CLOSED`, `422 MEMBERSHIP_NOT_ACTIVE` |
| `GET /api/v1/polls/{pollId}/responses` (`listPollResponses`) | `TEACHER` (автор) | → `{items:[{student: UserRef, group: StudyGroupRef, answers:[{questionId, optionIds}]}]}` по ФИО, затем id; анонимный — `409 INVALID_STATE`; не автор — `403` |

`PollSummary`: `id, title, endsAt, open, anonymous, voted` (у студента), `groups`. `PollResults`: `voted` (число), `questions:[{questionId, options:[{optionId, votes, share}]}]`, `share` — доля от проголосовавших, целые проценты. Персональная лента: варианты `POLL_CREATED` (`title, endsAt`) и `POLL_CLOSED` (`title, voted, eligible`). Все операции — `x-status: planned` до U1–U3.

## Implementation Units

### U0. Контракт и спека

- **Goal.** Контракт из таблицы выше, коды ошибок, варианты ленты; `module-seams.md`: события `PollCreated` и `PollClosed` (публикатор `poll`, слушатель `feed`); `docs/spec/test-plan.md` — строки матрицы доступа для пяти операций.
- **Verification.** Линтер контракта и `ContractCompatibilityIT` зелёные; `npm --prefix frontend run api:gen` без ручных правок; `node tools/check-agent-docs.mjs`.

### U1. Создание и чтение опросов

- **Goal.** П1–П3, П7: `createPoll`, `listPolls`, `getPoll` без голосования.
- **Files:** `backend/src/main/java/ru/campusrating/poll/api/PollController.java`, `poll/domain/{PollDraft,PollRules}.java`, `poll/internal/{PollService,PollRepository}.java`, `backend/src/main/resources/db/changelog/poll/<ts>-poll.sql`; тесты `backend/src/test/java/ru/campusrating/poll/PollIT.java`, `backend/src/test/java/ru/campusrating/poll/PollRulesTest.java`.
- **Test scenarios:**
  - Создание: опрос с двумя вопросами виден автору и студентам целевой группы; `endsAt` в прошлом, 0 и 21 вопрос, 1 и 11 вариантов, повтор варианта после `trim`, пустое название — `400` по полю.
  - Группа вне доступных — `403`, в том числе смесь доступной и недоступной; опрос и события не созданы (KTD23).
  - Недопущенный преподаватель — `403`; студент на создание — `403`; гость — `401`.
  - Другой преподаватель с доступом к той же группе и администратор — `403` на `getPoll`; студент другой группы — `403`; несуществующий — `404`.
  - `PENDING`-студент целевой группы видит опрос, `open: true`, `results: null`.
  - Список студента — опросы его группы в порядке из контракта; список преподавателя — только свои.
  - Окончание ровно в `now` по `MutableClock` — опрос завершён.

### U2. Голосование, статистика и анонимность

- **Goal.** П4–П6, П9: `votePoll`, `results`, `listPollResponses`.
- **Files:** `poll/domain/{Ballot,VoteValidation}.java`, `poll/internal/{VoteService,PollRepository}.java`, правка `PollController`; тесты `backend/src/test/java/ru/campusrating/poll/VoteValidationTest.java`, `backend/src/test/java/ru/campusrating/poll/PollVoteIT.java`, `backend/src/test/java/ru/campusrating/poll/PollAnonymityIT.java`.
- **Test scenarios:**
  - `SINGLE` с двумя вариантами — `400`; `MULTIPLE` с двумя проходит; пропущенный вопрос, вариант чужого вопроса, повтор варианта, ответ на вопрос дважды — `400` (`VoteValidationTest`, чистые функции).
  - Повторный голос — `409 ALREADY_VOTED`, счётчики не изменились.
  - Параллельные два голоса одного студента — ровно один успех.
  - Голос после окончания — `422 POLL_CLOSED`; `PENDING` — `422 MEMBERSHIP_NOT_ACTIVE`; студент не той группы — `403`; преподаватель — `403`.
  - До голоса `results: null`; после — числа и доли; после окончания у не голосовавшего — `null`.
  - Автор: `eligible` и `voted`; неанонимный — ответы по студентам; анонимный — `409 INVALID_STATE`; не автор — `403`.
  - Анонимность, проверка схемы: ни одна таблица модуля `poll` не содержит одновременно ссылку на вариант и на пользователя или участие, кроме `poll_named_choice`; после голосов в анонимном опросе в `poll_named_choice` нет его строк.
  - Анонимность, API и логи: ответы всех операций анонимного опроса и логи приложения при голосе (`DEBUG`, захват `OutputCaptureExtension`) не содержат пары «id студента — id или текст варианта».

  - Отклонённое создание (`403`) событий не публикует.

|---|---|
| Сопоставление по времени или порядку раскрывает автора анонимного голоса | Строки голоса нет, только счётчики (KTD2); системные поля PostgreSQL вне заявленной защиты (R35) |
| Конфликт с U15 по `MEMBERSHIP_NOT_ACTIVE` и `REJECTED` | Проверка «только `ACTIVE`» уже покрывает будущий `REJECTED`; дополнительных правок не нужно |
| Форма создания на 360 px перегружена | Вопросы — сворачиваемые блоки; скриншоты 360 px обязательны |

## Definition of Done
