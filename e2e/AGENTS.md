# E2E — правила для агентов

Playwright против полного стека из `docker-compose.e2e.yml` (ускоренный штраф: интервал 4 с, poll-period 1 с). Дополняет корневой `AGENTS.md`.

## Сценарии

- Каждый тест соответствует сценарию из `docs/spec/test-plan.md`: стабильный ID, предусловия, шаги, ожидание, негативные ветки, источник (R/AE).
- Доменный тест создаёт своих пользователей, факультет, кафедру, группу, точки и активности через `tests/base/support.ts`; из сида используется администратор для подготовки справочников и допуска. Тест не зависит от данных другого теста.
- Найденный баг сначала закрепляется тестом, потом исправляется.

## Как пользователь, а не как скрипт

- Локаторы — по ролям и подписям: `getByRole`, `getByLabel`, `getByText`. CSS-селекторы и `data-testid` — только когда иначе нельзя.
- Без `force: true` и кликов по скрытым элементам: если пользователь не видит кнопку, тест должен упасть.
- Ожидания — `expect.poll` и авто-ожидания Playwright, без `waitForTimeout`.
- Ключевые экраны — `toHaveScreenshot` на 360 и 1280 px.

## Нестабильность

- Нестабильный тест разбирается через trace viewer, а не лечится ретраями и увеличением таймаутов.
- Тесты штрафа ждут изменения АР опросом состояния с запасом в несколько интервалов.

## Команды

Из корня репозитория:

1. `npm --prefix e2e ci`, затем `npm --prefix e2e run check`.
2. `cd e2e` → `npx playwright install --with-deps chromium` → вернуться в корень.
3. `docker compose -p campus-e2e -f docker-compose.yml -f docker-compose.e2e.yml down -v`.
4. `docker compose -p campus-e2e -f docker-compose.yml -f docker-compose.e2e.yml up -d --build --wait`.
5. `npm --prefix e2e test`.
6. После прогона, в том числе при падении: `docker compose -p campus-e2e -f docker-compose.yml -f docker-compose.e2e.yml down -v`.

По умолчанию `baseURL` — `http://127.0.0.1:8090`; переопределение — `E2E_BASE_URL`. Проекты Chromium — 360×800 и 1280×800. Playwright стеком не управляет. `tests/smoke.spec.ts` проверяет форму входа и маршрутизацию nginx; `tests/base/` — регистрацию, сессии, точки, штраф, активности, бюджет, профиль, ленту и рейтинг со стабильными ID тест-плана. `support.ts` управляет отдельными API-сессиями и CSRF, уникальными email, справочниками и допуском преподавателя через API U13. Сроки считаются от серверного `Date`, ожидания идут опросом API. Скриншоты ключевых экранов сохраняются в `test-results/`, HTML-отчёт — в `playwright-report/`, trace — при падении.

## Уроки

Правила — как в разделе «Уроки» корневого `AGENTS.md`.

- Typecheck и lint e2e были собраны из флагов CLI с тремя правилами, чтобы не выходить за `Files`, и не ловили забытый `await` → ревьюер проверил удалением `await` → проверки — через `e2e/tsconfig.json` и `e2e/eslint.config.js` (`recommendedTypeChecked`); нужный для проверки смежный конфиг добавляется с пометкой, а не обходится флагами.
- Сценарий семестра и штрафа на общем стенде дал ложные FAIL: сид-семестр «Осень 2026» уже начался и начисляет новым студентам в первую минуту, а точка штрафует всех студентов выбранной группы → нашёл QA по истории `ledger_entry` → в тестах штрафа и семестра регистрировать своих студентов, проверять сумму проводок по точке или семестру (`source_id`), а не баланс, и учитывать сид-семестр (`backend/src/main/resources/db/changelog/`).
- POLL-01 упал по таймауту на `locator.check()` чекбокса группы: `frontend/src/theme/theme.css` расширяет область нажатия подписи на квадратик, и Playwright видит перекрытие → нашёл первый прогон e2e U16 → чекбоксы Mantine в e2e отмечать `check({ force: true })` или кликом по подписи, проверяя состояние после клика.
